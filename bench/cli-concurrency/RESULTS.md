## Method

All measured workload processes share a dedicated cgroup with a four-core CPU quota, affinity to four distinct physical cores (8–11), 16 GiB memory, and zero swap. The physical host is shared, with 64 logical CPUs; this is an enforced resource envelope, not a dedicated four-core virtual machine. The full test suite and long-running audit processes used other CPUs; lightweight orchestration still shares the physical host. Cold sessions retain the OS page cache.

Each task pair fixes and executes two separate generated coding tasks, preserves immutable inputs/checkers, writes fresh execution proofs, emits tool events and one result, and recalls a conversation-only random marker on its second turn. Comparisons use fresh adjacent original serial controls, pinned models/providers/efforts, and three or five repetitions. Codex and ZCode use separate Agent instances; other backends use multiple sessions on one Agent. Shared server serialization remains unchanged as required by the current specification.

The startup requirement is at most 2× original; the explicit work tolerance is 1.10×, for cold/warm p50 and nearest-rank p95. First-event latency includes inference and is not pure startup. The harness’s `work_seconds` omits initial inference, so complete-task ratios are shown separately while retaining the original strict verdict. Neither alone establishes isolated provider work. With three/five serial observations, p95 is the largest observation; these are operational checks with substantial provider and model variation. Concurrent groups pool more observations than the serial controls, so their tail estimators have different uncertainty. A missed gate is not by itself evidence that changed code caused a slowdown.

The slow native inference/tool intervals remain included in the failed work result. The [portable native phase records](evidence-2026-09-09/kimi-native-phases.json) include per-turn times, counts and clock bridges. A later five-repeat serial candidate control also failed warm request-to-result p95 (1.253×). ## Regression validation

`uv run pre-commit run --all-files` passed. `uv run pytest` passed 2,208 tests with 77 skips and 42 warnings in 719.35 s. The standalone benchmark suite passed 51 tests. Skips include opt-in paid-agent checks, unavailable Docker and localhost SSH; successful full-suite execution does not claim those integrations ran. The real coding workload uses permission bypass and ordinary two-turn read/edit/execute/resume; broader modes are covered only by the specific unit or native feature checks listed below. The dynamic ACP extension has no single enumerated official executable and is outside the built-in CLI matrix.

Installed Qwen completed nine native feature phases and Antigravity twelve against controlled local model replies, covering structured-output validation, ordinary/schema transitions, context retention, skill/config invalidation, process reuse and usage accounting. Negative controls reproduced the prior schema, usage, question-query and ctypes ownership failures.
